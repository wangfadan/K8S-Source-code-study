# Client-go的Informer机制
直接 clientset.CoreV1().Pods("").List() —— 这是一次性查询。但 K8s 控制器需要持续监听资源变化(增/删/改)并做出反应。如果每次都去 API Server 轮询,会给 API Server 造成巨大压力。
Informer 就是解决方案:它通过 List + Watch 机制,在本地维护一份资源缓存,并通过事件回调通知你变化,同时提供了本地索引查询能力。

## 核心组件
1. Reflector — "侦察兵"
- 负责 ListAndWatch:先 List 全量数据,然后建立 Watch 连接持续监听变化
- 将收到的对象包装成 Delta(增/删/改),推入 DeltaFIFO
2. DeltaFIFO — "缓冲队列"
- 一个先入先出的队列,存储的是 Delta(操作类型 + 对象)
- 保证同一对象的多个 Delta 按顺序处理
- 有去重逻辑(同一对象的多个更新可以合并)
3. Indexer — "本地缓存 + 索引"
- 本质是 ThreadSafeStore:一个带读写锁的 map,存储所有资源的最新状态
- 支持自定义索引函数(如按 namespace 索引)
4. SharedIndexInformer — "总指挥"
- 组合上述组件,对外提供统一接口
- 管理多个 ResourceEventHandler(事件监听器)
- 提供 Run() / AddEventHandler() / GetIndexer() 等方法
5. SharedInformerFactory — "工厂"
- 创建并缓存各种资源的 Informer
- 确保同一资源的 Informer 全局共享(避免重复 List/Watch)
